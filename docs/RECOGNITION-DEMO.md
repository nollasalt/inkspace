# 手写识别验证

这是独立实验窗口，用真实手写样本验证识别准确率、公式结构、连线关联、等待时间和纠错成本。正式 VS Code 插件、Ink Engine 和笔记格式保持原状，Demo 不会读取或改写已有笔记。

## 启动

在项目根目录运行：

```powershell
npm run demo:recognition
```

启动器构建界面和 Windows 文字识别辅助程序，然后打开独立窗口。依赖项目已有的 Node.js、Electron 和 Windows .NET Framework 编译器，不需要额外 npm 依赖。关闭窗口即可结束。

## Codex 路线

本机需安装官方 Codex CLI，并通过 `codex login` 登录。Demo 使用公开的 `codex exec --image --output-schema` 接口，复用已有登录；不读取、复制或导出身份凭据，不需要额外 API 密钥。

这是**本地界面 + 联网识别**，会消耗对应账户的 Codex 用量。只有手动点击识别按钮时才发送选区图片；不会在书写期间自动发送。用户配置不加载到这个实验请求中，模型输出被限制为转写及结构 JSON。

默认明确指定 **GPT-6 Luna + low 推理强度**，优先降低用量和延迟；可在识别按钮上方切换 **GPT-6.1 Sol + low**，用于复杂样本对照。模型选择会记住，不会在失败时自动换成更贵的模型。结果、测试历史和保存文件记录模型与推理强度，结果还显示 CLI 返回的输入/输出 tokens。此前没有指定模型的旧版没有记录实际型号，不能据此确认某次旧请求用了哪个模型。

Luna 支持图片输入和结构化输出，官方将其定位为高效率的集中提取任务模型：[模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)。ChatGPT 登录使用订阅账户的 Codex 用量，不能把 API 的每百万 tokens 价格直接当作这里的扣费。较低推理强度是成本和延迟的取舍，不保证真实手写准确率或固定秒数；仍需用同一份中文、公式和连线样本比较。

CLI 以只读模式运行，禁用 shell、子代理、浏览器、计算机操作、应用、插件、hooks、搜索及代码修改工具。识别请求在独立临时目录执行，不把项目源码当作识别上下文。临时图片和输出在任务结束后清理。若 CLI 未装到 npm 标准位置，可设置 `INKSPACE_CODEX_EXE` 指向官方原生可执行文件。

使用官方 `model_instructions_file` 配置将通用编程说明替换为精简的识别说明，禁用记忆注入，减少与识别无关的输入 tokens。权限限制保持不变；不改动全局 Codex 设置。[配置参数](https://learn.chatgpt.com/docs/config-file/config-reference)

官方说明：

- [Codex CLI 参数](https://learn.chatgpt.com/docs/cli/reference)
- [图片输入](https://learn.chatgpt.com/docs/image-inputs)

## Windows 路线

调用本机已安装的 `Microsoft.Ink` 文字识别器，默认选中简体中文。无需网络和服务密钥。它只作为文字识别基线，不代表数学结构或 Mindmap 理解能力；导入图片时此选项禁用。

输入坐标从 CSS 像素转换为 HIMETRIC，保留相对布局；框选时截断跨越边界的笔画，与图片裁切范围一致。识别器候选照实展示，不伪造中文识别置信度。

## 实测步骤

1. 写一句实际会使用的中文，分别用 Windows 与 Codex 识别同一选区。
2. 写一组分式、上下标、求和等实际公式，使用 Codex 识别。检查 LaTeX 原文与排版预览。
3. 写一小片文字、公式与箭头混合结构，检查节点位置及连接方向。不要只看转写是否流畅。
4. 在“测试对照”填写正确转写，查看字符编辑距离；确认需要手动改几处，以及等待时间能否接受。

界面也支持导入或粘贴现有笔记截图。框选后点击“复制选区图片”，可以直接粘贴到当前 Codex 对话中人工比对。Demo 手写采样使用 Pointer Events 和 coalesced events，绘制复用项目的 Xournal++ 轮廓；此实验不用于评判正式 Raw Input 引擎性能。

识别输出包括原文 Markdown、文字/公式节点、归一化节点位置、连接及不确定项。文字与公式转写、结构解释分开展示；修改转写不会自动重建连接。它们是待核对的实验结果，尚未接入正式笔记模型。

“保存确认结果”只保存结果 JSON、原始转写、耗时、对照文本及纠错操作数，不保存输入笔迹或图片，也不会创建 `.ink` 文件。纠错操作数统计输入事件与候选/结构修改次数，不是错误字符数量。CER 使用 Unicode 字符、包含空格与标点，不衡量公式等价性或关系语义。

## 验证与限制

```powershell
npm run test:recognition
# 显式联网测试（先执行上面的本地测试生成合成样本）：
npm run test:recognition:codex
```

本地测试覆盖结果校验、选区裁切、中文字符度量、不含笔迹的结果导出、实际 Windows 识别、取消任务、笔/鼠标选区所有权、公式预览、节点定位和过时结果保护。联网测试只使用合成的 `1+1=2` 笔画，验证 Codex 调用与数学结果结构，不作为真实笔迹准确率证据。

运行日志及测试报告位于 `artifacts/recognition-demo/`，此目录已被 Git 忽略。网络错误、取消或无效识别结果均保留画布输入，不进行自动转换。需要用户真实笔迹测试后，才能决定默认识别路线和是否继续开发结构化输入。
